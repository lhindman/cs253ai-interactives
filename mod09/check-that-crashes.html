The check that crashes

Four functions an assistant wrote in one reply. record_matches_level checks for NULL; count_by_level does not, and leans on that check instead. Step through the three calls in main and watch the third one get past the check and crash on it.

Each struct LogRecord here is 16 bytes, so element i is at records + 16 × i. With records NULL there is no array: every one of these addresses is in the first page of memory, where nothing is ever mapped, so any read there crashes. The check only catches the first.

      

    

  


  
Keys: → or Space step, ← back, P play. Measured on Ubuntu 24.04 with gcc 13.3.0 at -O0: the output, the crash and the backtrace are pasted from a real run. Strictly, computing &records[1] from a NULL records is already undefined behaviour; 0x10 is what this compiler does with it, which is why the address looks so believable.

  
In Lab 09 the same mistake looks the same with a bigger number. LogRecord there is 144 bytes, so the second element is at 0x90, and make test dies with a bare Segmentation fault. gdb -batch -ex run -ex bt ./run_tests shows you where.
